단계형 실습 페이지 표준 (폰 화면 + 말풍선 · 캐릭터)

“앱을 눌러요 → 입력해요 → 완료!”처럼 단계(STEPS)마다 말풍선이 바뀌고 눌러야 할 곳을 손가락으로 알려 주는 실습 페이지의 기준입니다. 이 구조로 만든 페이지는 같은 방법으로 캐릭터 포즈·손가락·클릭 영역을 화면에서 보며 맞출 수 있습니다(?edit). 기준 예시는 sa/02/page08.html · sa/02/page10.html입니다. 새 페이지는 아래 순서대로 만들고, 기존 페이지는 맨 아래 “적용 현황”을 보고 하나씩 맞춥니다.

    1. 구성 요소 6가지

    요소쓰는 것어디서 고치나
    ① 말풍선 + 캐릭터 세트공용 .guide-set(말풍선 .guide-bubble.is-center + .guide-character) + initGuideSay. 기본 포즈는 main(sa_main.png)각 단계 줄의 pose: '…'
    ② 단계 목록 STEPS단계마다 { pose, bubble, … hit: '이름' } 한 줄. hit = 지금 눌러야 하는 곳의 data-hit 이름페이지 안 STEPS
    ③ 손가락 FGconst FG = { 이름: [dx, dy] } — 손가락 위치 보정. pointFingerAt(target, { …, dx, dy }) 로 넘김?edit 에서 손가락을 눌러 맞춤
    ④ 클릭 영역 HOTconst HOT = { 이름: [dx, dy, dw, dh] } + BoxEdit.hitPad(hits, HOT). 버튼 모양은 그대로, 눌리는 범위만 옮기거나 키움/줄임(음수 가능). 값은 버튼 테두리 바깥 기준(테두리가 있어도 [0,0,0,0] 이면 버튼 전체와 같음). 모두 0 이면 평소 화면에는 아무것도 안 만듦. 눌러야 할 곳은 반드시 실제 요소여야 함(아래 5번)?edit 에서 영역을 눌러 맞춤
    ⑤ 편집 모드 ?editjs/box-edit.js 의 BoxEdit.stepEdit — 단계 이동·포즈판(오른쪽 아래)·손가락·영역 조정이 한 화면에서 됨. 주소의 step 이 단계 이동 때마다 같이 바뀌고 새로고침하지 않음. 단계 번호가 % 좌표면 unit: 0.1, 단계 번호는 모든 페이지가 1부터(?edit&step=1 이 첫 단계, 0 단계는 없음), 화면 속 다른 박스까지 옮겨야 하면 apply·name 을 직접 줌(주면 기본 동작을 대신함). BoxEdit.fingerTag() 는 여러 번 불러도 한 번만 걸림—
    ⑥ 눌러야 할 곳 깜빡임공용 .hit-pulse 하나(분홍 테두리 1.2초, 원래 그림자가 있는 요소도 이어서 깜빡임). 화면이 줄어든 그림 안이면 --pulse-w 로 두께를 보정. 첫 화면(앱 아이콘 로고 화면)은 펄스 없이 손가락만. 편집 화면에서도 깜빡임이 보임클래스를 붙이거나 pointFingerAt(el, { pulse: true })

    2. 만드는 순서(코드 뼈대)

    1

    마크업 — 말풍선·캐릭터는 화면에 세트 하나만(단계마다 세트를 따로 두지 않고 say() 로 바꿈). 캐릭터 그림은 포즈와 상관없이 같은 위치·크기라 좌표를 따로 쓰지 않음. box-edit.js 는 common.js 다음에 불러옴.

    <div class="guide-set is-main" id="p08Set">
  <p class="guide-bubble is-center" id="p08Bubble"></p>
  <div class="guide-character"><img id="p08Char" src="../img/character/sa_main.png" alt="메인 캐릭터"></div>
</div>
…
<script src="../../js/common.js"></script>
<script src="../../js/box-edit.js"></script>
    2

    단계·말풍선 — say(문구, 포즈). 포즈를 안 적은 단계는 main.

    const say = initGuideSay({ bubble: bubble, img: $('p08Char'), set: $('p08Set') });
const STEPS = [
  { pose: 'wink_point2', bubble: '먼저, 템플릿을 골라볼까요?', screen: 'home', hit: 'template' },
  { bubble: '마음에 드는 템플릿을 선택해요.', screen: 'list', pick: 'tpl' },   // pose 없음 = main(표를 보기 쉽게 모든 줄에 pose: '' 를 적어도 됨)
];
function render() { const step = STEPS[index]; say(step.bubble, step.pose || 'main'); … }
function go() { index += 1; BoxEdit.syncStep(index + 1); render(); }
    3

    손가락 · 클릭 영역 — 눌러야 할 요소는 분홍 테두리로 깜빡임 — 클래스 .hit-pulse 하나로 통일(폰 틀 .cv 안팎 모두, 1.2초). 직접 붙이거나 pointFingerAt(el, { pulse: true }) 가 손가락과 함께 붙였다 뗌. 깜빡이지 않을 단계는 클래스를 안 붙임. 첫 화면(앱 아이콘 로고 화면)은 펄스를 쓰지 않고 손가락만. 값은 처음엔 전부 0. 화면에서 맞춘 뒤 표시줄 값을 옮겨 적음.

    화면이 그대로인 페이지는 BoxEdit.hitPad(hits, HOT) 한 번, 단계마다 화면을 innerHTML 로 새로 그리는 페이지(예: sa/15 page08, sa/01 page10, sa/12)는 눌러야 할 요소를 그릴 때마다 BoxEdit.padEl(요소, 이름, HOT) 을 부름. Papago 화면(sa/12)은 PP.finger(요소, { key, FG, HOT }) 하나로 손가락·깜빡임·영역을 붙임.

    const FG  = { template: [0, 0], elements: [0, 0] };
const HOT = { template: [0, 0, 0, 0], elements: [0, 0, 0, 0] };
BoxEdit.hitPad(hits, HOT);                                   // hits = phone.querySelectorAll('[data-hit]')
const fg = FG[step.hit] || [0, 0];
pointFingerAt(target, { onMain: true, beside: true, dx: fg[0], dy: fg[1] });
// 손가락이 화면 아래로 잘리지 않게 하는 보정은 편집 모드에서는 끔:
if (!BoxEdit.on) document.querySelectorAll('.js-point-finger').forEach((f) => { f.style.top = Math.min(parseFloat(f.style.top), 850) + 'px'; });
    4

    편집 모드 — 페이지 맨 아래 render() 바로 앞에 붙임. 앞 단계에서 정해지는 값(고른 템플릿 등)은 prep 에서 미리 채움.

    BoxEdit.stepEdit({
  key: () => STEPS[index].hit || '?',                 // 지금 단계에서 눌러야 할 곳 이름(FG·HOT 의 키)
  count: STEPS.length + 1,
  get: () => index + 1,
  set: (n) => { index = Math.max(0, Math.min(n, STEPS.length) - 1); },
  go: (n) => { if (n < 1) return; index = n - 1; BoxEdit.syncStep(n); render(); },
  label: (n) => '단계 ' + n + ' / ' + STEPS.length,
  say, bubble, img: $('p08Char')                       // 포즈판용
});
render();

    손가락 표시·클릭 영역 편집·단계 이동·포즈판을 BoxEdit.stepEdit 한 번으로 연결합니다(?edit 가 아니면 아무 일도 안 함). 앞 단계에서 정해지는 값(고른 템플릿 등)은 set/go 안에서 미리 채움.

    • 단계를 옮겨도 새로고침하지 않음 — go() 는 화면을 다시 그리고, 앞 단계에서 켜 둔 것(모달·오답 팝업·재생 중 소리·타이머·이전 선택)을 되돌려야 함. 단계 사이에서 끝나지 않은 타이머는 번호표(tok)로 무시.
    • 편집 모드에서는 눌러도 진행하지 않음 — 눌러야 할 곳을 클릭해 위치를 맞추는 중이므로 클릭·자동 진행(타이머)·소리 재생이 단계를 넘기지 않게 막음. 단, 한 단계 안에서 말풍선이 더 바뀌는 곳(예: 정답을 고른 뒤 "좋아요!")은 눌러서 볼 수 있어야 포즈를 맞출 수 있음.
    • 말풍선 문구·포즈는 한 곳에 — STEPS 줄이나 SAYS 표에 모아서 실제 진행과 편집 화면이 같은 값을 쓰게 함(코드 곳곳에 say('문구', '포즈') 를 흩어 두지 않음).
    • 이야기 삽화 번호 등 "지나온 횟수"로 정하는 값은 단계 위치로 계산 — 건너뛰거나 뒤로 가도 맞게 나옴.

    3. 편집 모드 쓰는 법

    • 열기 — 페이지 주소 뒤에 ?edit&step=N. 예: sa/02/page10.html?edit&step=10. 단계를 넘기면 주소의 step 도 따라 바뀜(새로고침해도 그 단계).
    • 단계 이동 — ] [ (또는 PageDown / PageUp), 왼쪽 위 [이전][다음].
    • 캐릭터 포즈 — 오른쪽 아래 포즈판에서 그림을 누르면 그 단계 캐릭터가 바로 바뀜. 포즈 이름(wink_present, 따옴표 없이)이 클립보드에 복사되니 pose: '…' 나 say(문구, '…') 의 따옴표 안에 붙여 넣음.
    • 손가락(FG) — 손가락(붉은 점선 박스)을 클릭 → 방향키 1px(Shift 10px). 표시줄(복사되는 값)은 표의 줄 모양 이름: [dx, dy], — 코드의 FG 표에서 같은 이름 줄을 통째로 바꿔 넣음(없는 이름이면 줄을 추가).
    • 클릭 영역(HOT) — 눌러야 하는 버튼 위의 붉은 점선 박스를 클릭 → 방향키로 이동, Alt+방향키로 폭·높이. 표시줄(복사되는 값) 이름: [dx, dy, dw, dh], 를 코드의 HOT 표에서 같은 이름 줄과 바꿔 넣음. 손가락과 겹치면 손가락이 먼저 잡히니 영역은 손가락이 없는 가장자리를 누름.
    • 화면에 보이는 박스 — 클릭 영역(붉은 점선 박스)은 지금 눌러야 할 곳(깜빡임 .hit-pulse 이거나 손가락이 가리키는 곳)만 나옴. 다른 버튼의 박스는 숨김(공용 편집 도구가 처리). 눌러야 할 곳의 깜빡임도 편집 화면에서 그대로 보임(첫 화면의 앱 아이콘은 깜빡임 없이 손가락만).
    • 값은 자동으로 코드에 쓰이지 않음 — 표시줄의 [복사](현재 값) · [전체 복사](모은 값 전부)로 복사해 붙여 넣음.

    5. 눌러야 할 곳은 실제 요소로 — 그림 위에 빈 버튼을 얹지 않기

    그림(PNG) 위에 투명한 빈 버튼을 얹어 "눌리는 곳"을 만들면 표준 FG·HOT 으로 조절할 수 없습니다. 눌러야 할 곳은 CSS로 직접 그린 실제 버튼으로 만들고, 그 요소에 data-hit 이름을 붙입니다. 예: sa/11/page09.html 의 하단 도구 막대(.tbx)·글꼴 칩(.tbx-chip)·다운로드 아이콘.

    • 새로 그릴 때 — 원본 그림을 픽셀로 재서 위치·크기를 맞추고(예: 글꼴 칩은 알약 154×53·보라 테두리 3px·안쪽 연회색, 화살표 원 54px·테두리 없이 그림자), 눌러야 할 요소에만 data-hit 을 붙임. 이전 클릭 영역과 손가락 위치는 새 요소 기준으로 다시 계산해 HOT·FG 값으로 옮겨 같은 곳이 눌리게 함.
    • 이미 코드로 그려진 화면이면(예: sa/10 의 vllo-ui.js) 새로 그리지 않고, 페이지에 TARGET = { 이름: [선택자, 글자(앞부분)] } 표를 두고 그 단계의 요소를 찾아 data-hit·hit-pulse·HOT 을 붙임(sa/10 · sa/04 page13 · sa/12 의 PP.finger).
    • 새 클래스 이름은 공용 CSS 와 겹치지 않게 — css/common.css 에 .u-tb · .u-ok · .u-chip · .u-fchip 같은 이름이 이미 있어서, 같은 이름으로 만들면 서로 덮어써 화면이 깨짐(실제로 "정사각형" 칩이 커졌음). 이름을 정하기 전에 grep 으로 확인하고 페이지 전용은 접두사(tbx- 등)를 붙임.
    • 그림만 있어서 요소를 만들 수 없는 경우(화면 캡처 조각·p09_screen_N.png)는 기본 위치 표 HIT(이름 → [x%, y%, 폭%, 높이%])에 눌러야 할 곳을 모으고, HOT 은 다른 페이지와 똑같이 px 보정으로 둠. 같은 자리는 같은 이름으로 씀. 예: sa/08 page10 · sa/13·14 page09.
    • 줄어든 화면(transform: scale) 안에서는 깜빡임 테두리 두께가 줄어 보이므로, 그 화면 요소에 --pulse-w(예: 5.4px)를 주어 보정.
    • 배경이 분홍·빨강이라 깜빡임이 안 보이면 그 요소에 --pulse-c(예: #fff)를 주어 색만 바꿈(공용 키프레임이 읽음). 예: sa/14 page09 4단계(빨간 머리글 위 메뉴 버튼).

    6. 자주 만나는 함정

    • 포즈 값 — say(문구, 포즈) 에서 포즈를 빈 문자열('')로 주면 sa_main, 아예 안 주면(undefined) 지금 포즈를 그대로 둠. 단계 표에서는 빈 값 pose: '' 로 적어 두는 것이 안전.
    • 폰 홈 화면의 상단바·하단바 — <div class="phone-status">·<div class="phone-nav"> 를 비워 두면 공용이 채움. 어두운 폰 틀(.phone-screen.is-dark) 안의 밝은 홈 화면에서는 상단바 글자가 흰색이 되어 안 보이므로 상단바·하단바에 is-light 를 붙임(예: sa/13·14 page09 의 홈). 그림에 상단바가 없으면(sa/13 page09 4~11번째) 폰 안에 phone-status 하나를 두고 그 단계에서만 보이게 함.
    • 단계가 바뀔 때 남은 클릭 — 눌러서 화면을 다시 그리는 순간 같은 클릭이 새 화면의 "빈 곳 누름" 검사에 걸려 오답 소리가 날 수 있음. 검사에서 e.target.isConnected 로 이미 사라진 요소의 클릭은 무시하고, 단계가 바뀔 때마다 검사를 지움(예: sa/13 page09).
    • 처음에는 안내 없이 → 틀리면 힌트(예: sa/13 page09 6단계) — 처음엔 손가락·깜빡임 없이 화면만 보여 주고, 눌러야 할 곳이 아닌 곳을 누르면 오답 소리 + 깜빡임(.hit-pulse)과 손가락을 붙임. ?edit 에서는 위치를 맞춰야 하므로 처음부터 보임.
    • 깜빡임 색 — 배경이 분홍·빨강이라 안 보이면 --pulse-c (5번 절).

    7. 공용 도우미(페이지에서 다시 만들지 않기)

    • BoxEdit.fgo(FG, '이름', { pulse: true }) — FG[이름] 의 [dx, dy] 로 pointFingerAt 옵션을 만들고 지금 이름을 기억함. BoxEdit.fingerTag() 를 인자 없이 부르면 그 이름이 표시줄에 나옴(fgKey 변수를 따로 두지 않음).
    • showIf(요소, true|false) — .is-hide(공용 CSS, display:none)를 붙였다 뗌.
    • placePct(요소, [왼쪽%, 위%, 폭%, 높이%(, 모서리px)]) — 부모 기준 % 위치. 그림 위 영역(HIT 표)을 놓을 때.
    • typeText(요소, '문구', { speed, html, render, clear, onTick, onDone, doneDelay }) — 글자를 한 자씩 써 넣는 연출(채팅 답변·프롬프트 입력). 페이지마다 setInterval 을 따로 쓰지 않음. 예: sa/09 page09 · sa/05 page08.
    • playAppLaunch({ icon, text, logo, colors, onMid, onDone }) — 폰 앱 실행 연출(약 1.6초): 앱 아이콘 자리에서 흰 카드가 펼쳐져 화면을 덮고 → 로고가 둥근 사각형이 되며 글자가 나타나고 → 그라데이션이 노이즈(그레인) 질감으로 중앙에서 번져 → 글자는 둔 채 다음 화면으로 크로스페이드. onMid 가 크로스페이드 시작 때 불려 거기서 다음 화면을 그리면 됨. 단계를 되돌릴 때는 cancelAppLaunch(). 색은 colors: [노랑, 주황, 분홍](기본 Suno). 예 sa/06/page09.html
    • ICONS.이름 — 폰 화면 아이콘 전부(182개)가 js/common.js 의 표에 한 번씩만 있음. 같은 뜻의 아이콘을 페이지에서 따로 그리지 않고 가져다 씀(여러 앱이 같이 쓰는 40개 — 나머지는 앱별로 묶어 둠). 이름·쓰는 곳 목록은 공용 아이콘.
    • 폰 화면의 한글 키보드 — 마크업을 복사하지 않고 비어 있는 <div class="kbd-cj"></div> 만 둠(공용 initKbdCj 가 채움. 예: sa/01 page10 · sa/09 page09).
